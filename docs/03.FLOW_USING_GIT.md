# Hướng dẫn dùng Git cho dự án Food Store Manager

> **Repo:** https://github.com/hoangtuanqn/food-store-manager
> **Công cụ:** NetBeans 13 + JDK 8

---

## 0. Git là gì? Vì sao phải dùng?

Cả nhóm cùng code chung một dự án. Nếu mỗi người tự sửa rồi gửi file qua Zalo cho nhau thì code rất dễ bị ghi đè hoặc mất. **Git** giải quyết chuyện này: nó lưu lại mọi thay đổi, ghi rõ ai sửa gì và sửa lúc nào, và cho phép nhiều người cùng làm mà không giẫm lên nhau.

**Vài từ bạn sẽ gặp:**

| Từ | Hiểu đơn giản |
| --- | --- |
| **Repository (repo)** | Thư mục dự án được lưu trên GitHub |
| **Clone** | Tải dự án từ GitHub về máy (chỉ làm 1 lần) |
| **Branch (nhánh)** | Một "bản sao" riêng của dự án để bạn sửa thoải mái, không ảnh hưởng người khác |
| **`main`** | Nhánh chính, chứa code chuẩn của cả nhóm. **Không ai được sửa trực tiếp trên nhánh này** |
| **Commit** | Bấm "lưu" một mốc thay đổi, kèm một câu mô tả bạn đã làm gì |
| **Push** | Đẩy các commit từ máy bạn lên GitHub |
| **Pull** | Kéo code mới nhất của cả nhóm từ GitHub về máy bạn |
| **Pull Request (PR)** | "Xin phép" gộp nhánh của bạn vào `main`. Lead xem, thấy ổn thì gộp |

**Cách làm việc của nhóm, tóm gọn trong 1 dòng:**

```
Lấy code mới từ main → Tạo nhánh riêng → Code → Commit → Push → Tạo Pull Request → Lead duyệt và gộp vào main
```

## 1. Clone dự án về máy (chỉ làm 1 lần)

1. Mở **NetBeans 13**.
2. Trên thanh menu, chọn **Team → Git → Clone...**
3. Ở ô **Repository URL**, dán vào:
   ```
   https://github.com/hoangtuanqn/food-store-manager.git
   ```
   Hai ô User và Password để trống, rồi bấm **Next**.
4. Màn hình tiếp theo liệt kê các nhánh. Tick vào **`main`**, bấm **Next**.
5. Ở ô **Parent Directory**, bấm **Browse...** và chọn nơi lưu dự án, ví dụ `D:\Projects`. Các ô còn lại giữ nguyên, bấm **Finish**.
6. Chờ NetBeans tải xong. Khi có bảng hỏi mở project, bấm **Open Project**.
7. Bên tab **Projects** (góc trái) sẽ xuất hiện **`FoodStore [main]`**. Chữ trong ngoặc vuông cho biết bạn đang đứng ở nhánh nào.
8. Bấm **F6** để chạy thử. Nếu cửa sổ **Output** ở dưới hiện menu console là đã xong.

> **Lưu ý:** nếu thấy menu **Team** bị mờ, không bấm được, hãy click vào project **FoodStore** ở tab Projects trước rồi thử lại.

### Hiểu màu tên file trong NetBeans

NetBeans tô màu tên file để bạn biết file nào đã thay đổi:

| Màu | Nghĩa |
| --- | --- |
| Đen (bình thường) | File chưa sửa gì |
| **Xanh lá** | File mới tạo, chưa commit |
| **Xanh dương** | File đã sửa, chưa commit |
| Xám | File Git bỏ qua (như `build/`, `dist/`), không cần quan tâm |
| **Đỏ** | Bị conflict (đụng code với người khác). **Báo Lead ngay** |

Muốn xem danh sách tất cả file đã sửa, chọn **Team → Show Changes**.

## 2. Quy tắc đặt tên nhánh

**Cấu trúc:**

```
<type>/<short-description>
```

- Viết bằng **tiếng Anh**, toàn bộ **chữ thường**
- Các từ nối với nhau bằng dấu gạch ngang `-`
- Không dấu cách, không dấu tiếng Việt, không dùng `_`

**Các type được dùng:**

| Type | Dùng khi | Ví dụ |
| --- | --- | --- |
| `feat` | Làm chức năng mới | `feat/add-product` |
| `fix` | Sửa lỗi | `fix/vip-discount` |
| `refactor` | Sắp xếp lại code cho gọn, chức năng giữ nguyên | `refactor/product-service` |
| `docs` | Sửa README hoặc tài liệu | `docs/update-readme` |
| `chore` | Việc lặt vặt (cấu hình, `.gitignore`...) | `chore/update-gitignore` |

**Ví dụ theo task trong dự án:**

| Task được giao | Tên nhánh |
| --- | --- |
| Thêm chức năng thêm sản phẩm | `feat/add-product` |
| Thêm chức năng tìm khách hàng theo tên | `feat/search-customer-by-name` |
| Chặn bán sản phẩm đã hết hạn | `feat/block-expired-product` |
| Sửa lỗi tính sai giảm giá cho khách VIP | `fix/vip-discount` |
| Sửa lỗi nhập chữ vào menu thì chương trình bị crash | `fix/menu-input-crash` |

**Sai và đúng:**

| ❌ Sai | Lý do | ✅ Đúng |
| --- | --- | --- |
| `tuan` | Không biết nhánh làm gì | `feat/add-product` |
| `them-san-pham` | Viết tiếng Việt | `feat/add-product` |
| `Feat/Add_Product` | Có chữ hoa và dấu `_` | `feat/add-product` |
| `feat/add-product-and-fix-menu` | Một nhánh làm 2 việc | Tách thành 2 nhánh |

## 3. Quy tắc viết commit message

**Cấu trúc:**

```
<type>: <short description>
```

- Viết bằng **tiếng Anh**, **chữ thường**
- Sau dấu `:` luôn có **1 dấu cách**
- Câu mô tả ngắn gọn, nói rõ **bạn đã làm gì**

| Type | Dùng khi | Ví dụ |
| --- | --- | --- |
| `feat` | Thêm chức năng mới | `feat: add product creation` |
| `fix` | Sửa lỗi | `fix: wrong discount for vip customer` |
| `refactor` | Sắp xếp lại code | `refactor: move validation out of ProductService` |
| `style` | Chỉ format code, đổi tên biến | `style: format CustomerView` |
| `docs` | Sửa tài liệu | `docs: update readme` |
| `chore` | Việc lặt vặt | `chore: update gitignore` |

**Sai và đúng:**

| ❌ Sai | Lý do | ✅ Đúng |
| --- | --- | --- |
| `update` | Không biết đã làm gì | `feat: add product creation` |
| `them chuc nang` | Viết tiếng Việt | `feat: add product creation` |
| `Feat: Add product` | Viết hoa | `feat: add product` |
| `feat:add product` | Thiếu dấu cách sau `:` | `feat: add product` |

> **Mẹo:** mỗi khi xong một phần nhỏ và chạy được, hãy commit luôn. Ví dụ làm chức năng thêm sản phẩm thì có thể chia thành 2–3 commit: phần nhập dữ liệu, phần kiểm tra dữ liệu, phần lưu. Đừng code cả ngày rồi mới commit một lần.

## 4. Quy trình làm một task (làm đúng thứ tự)

### Bước 1: Về nhánh `main`
1. Chọn **Team → Branch/Tag → Switch To Branch...**
2. Ở ô **Branch**, chọn `main`, rồi bấm **Switch**.
3. Kiểm tra tab Projects đã hiện `FoodStore [main]`.

### Bước 2: Lấy code mới nhất của cả nhóm
> Vì sao phải làm bước này? Trong lúc bạn nghỉ, các bạn khác có thể đã gộp code mới vào `main`. Nếu không kéo về, bạn sẽ code trên bản cũ và dễ bị conflict về sau.

1. Chọn **Team → Remote → Pull...**
2. Màn hình đầu chọn `origin`, bấm **Next**.
3. Tick `main`, bấm **Finish**.
4. Đợi cửa sổ Output báo xong. Nếu không có gì mới, nó cũng chỉ báo xong, không sao cả.

### Bước 3: Tạo nhánh mới cho task
1. Chọn **Team → Branch/Tag → Create Branch...**
2. Điền:
   - **Branch Name:** tên nhánh theo quy tắc ở Mục 2, ví dụ `feat/add-product`
   - **Revision:** để `main`
   - **Tick ô `Checkout Created Branch`** (để chuyển luôn sang nhánh mới)
3. Bấm **Create**.
4. **Kiểm tra:** tab Projects phải hiện `FoodStore [feat/add-product]`. Nếu vẫn thấy `[main]` thì **chưa được code**, hãy làm lại bước này.

### Bước 4: Code
- Code bình thường, bấm **F6** để chạy thử.
- Các file bạn sửa sẽ chuyển sang màu xanh dương, file mới tạo sẽ có màu xanh lá.

### Bước 5: Commit (lưu thay đổi)
1. Chọn **Team → Commit...**
2. Cửa sổ Commit hiện ra:
   - Ô **Commit Message** (phía trên): nhập message theo quy tắc ở Mục 3, ví dụ `feat: add product creation`
   - Danh sách **Files to Commit** (phía dưới): là các file sẽ được lưu
3. **Kiểm tra danh sách file:**
   - Chỉ giữ tick những file bạn **thực sự sửa cho task này**
   - **Bỏ tick** các file trong thư mục `data/` (`products.txt`, `customers.txt`, `orders.txt`). Những file này tự thay đổi khi bạn chạy thử chương trình
4. Bấm **Commit**.
5. Các file vừa commit sẽ trở lại màu đen. Như vậy là commit thành công.

> Commit chỉ lưu trên **máy bạn**. Người khác chưa thấy được gì cho tới khi bạn Push.

### Bước 6: Push (đẩy lên GitHub)
1. Chọn **Team → Remote → Push...**
2. Chọn `origin`, bấm **Next**.
3. Tick **nhánh của bạn** (ví dụ `feat/add-product`), **không tick `main`**, rồi bấm **Next** → **Finish**.
4. Lần push đầu tiên, NetBeans sẽ hỏi đăng nhập GitHub. Nếu bạn chưa biết nhập gì, **hỏi Lead**.
5. Cửa sổ Output báo push thành công là xong.

### Bước 7: Tạo Pull Request
1. Mở trình duyệt, vào https://github.com/hoangtuanqn/food-store-manager
2. Bạn sẽ thấy một khung vàng ghi tên nhánh vừa push, kèm nút **Compare & pull request**. Bấm vào nút đó.
   - Nếu không thấy khung vàng: vào tab **Pull requests → New pull request**, ô `base` chọn `main`, ô `compare` chọn nhánh của bạn.
3. Điền thông tin:
   - **Title:** ghi giống commit message, ví dụ `feat: add product creation`
   - **Description:** vài dòng mô tả bạn đã làm gì, ví dụ:
     ```
     - Add menu option to create a new product
     - Validate price and expiration date
     - How to test: Run → choose 1 → choose 1 → enter product info
     ```
4. Bấm **Create pull request**.
5. Xong. Bạn báo Lead là đã tạo PR.

### Bước 8: Nếu Lead yêu cầu sửa
- Ở NetBeans, **giữ nguyên nhánh đó**, không tạo nhánh mới.
- Sửa code → **Commit** (Bước 5) → **Push** (Bước 6).
- Pull Request trên GitHub sẽ tự cập nhật, **không cần tạo PR mới**.

### Bước 9: Sau khi Lead đã gộp (merge)
- Trên GitHub, PR của bạn sẽ chuyển sang trạng thái tím **Merged**.
- Quay lại **Bước 1** (về `main`) và **Bước 2** (Pull) để lấy code mới nhất, có cả phần bạn vừa làm.
- Nhận task mới thì bắt đầu lại từ **Bước 3**.

## 5. Gặp sự cố thì làm gì?

| Tình huống | Cách xử lý |
| --- | --- |
| Lỡ code trên `main` mà **chưa commit** | Làm ngay Bước 3 để tạo nhánh mới. Code bạn đang viết sẽ tự chuyển theo sang nhánh mới, không bị mất |
| Lỡ commit trên `main` | **Đừng push**. Báo Lead |
| Sửa hỏng 1 file, muốn quay lại như ban đầu | Chuột phải vào file → **Git → Revert Modifications...** → bấm **Revert** |
| Pull báo lỗi vì đang có file chưa commit | Commit các file đó trước (hoặc Revert nếu không cần), rồi Pull lại |
| Push báo lỗi đăng nhập | Báo Lead |
| File hiện **màu đỏ** hoặc thấy chữ **conflict** | **Dừng lại, không tự sửa, báo Lead** |
| Không hiểu NetBeans đang báo gì | Chụp màn hình gửi Lead |

## 6. Những điều KHÔNG được làm

- ❌ Code hoặc commit khi tab Projects đang hiện `[main]`
- ❌ Commit các file trong thư mục `data/`
- ❌ Viết commit message vô nghĩa như `update`, `fix`, `final`
- ❌ Một nhánh làm nhiều task khác nhau
- ❌ Xóa thư mục dự án rồi clone lại khi chưa hỏi Lead
