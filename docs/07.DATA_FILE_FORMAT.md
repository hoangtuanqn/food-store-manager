# Lưu dữ liệu ra file

Tài liệu này giải thích cách chương trình lưu dữ liệu ra file (yêu cầu File I/O của đề: lưu sản phẩm, khách hàng, giao dịch) và **hướng dẫn từng bước để làm cho một loại dữ liệu**. Các thẻ TASK-20 đến TASK-23 đều làm theo cách này.

## 1. Ý tưởng chung

- Mỗi `Repository` đang giữ dữ liệu trong một `List` trong bộ nhớ. Tắt chương trình là mất.
- Muốn giữ lại thì: **đọc** `List` từ file khi khởi động, và **ghi** `List` ra file sau mỗi lần thay đổi.
- Lưu dạng **binary** bằng Java serialization. Không cần tự viết code chuyển đối tượng thành chữ rồi tách chữ lại: Java làm giúp, chỉ cần gọi 1 hàm để ghi và 1 hàm để đọc.

## 2. Serializable là gì? Vì sao model phải `implements Serializable`?

Serialization là việc biến một đối tượng (ví dụ một `FoodProduct` với tên, giá, số lượng, ngày...) thành dãy byte để ghi ra file, và ngược lại là đọc dãy byte đó để dựng lại đúng đối tượng.

Java chỉ làm việc này với lớp được **đánh dấu cho phép**, bằng cách thêm `implements Serializable`. Đây là interface rỗng, không có hàm nào phải viết, chỉ là một dấu "lớp này được phép ghi ra file":

```java
import java.io.Serializable;

public class FoodProduct implements Serializable {
    private String productId;
    private String name;
    // ... giữ nguyên như cũ
}
```

Cần nhớ:

- Lớp nào **được lưu thì phải Serializable**, và mọi lớp mà nó **giữ làm trường** cũng phải Serializable. Ví dụ `Order` giữ `Customer` và danh sách `OrderDetail`, nên cả `Order`, `Customer`, `OrderDetail` đều phải Serializable.
- `String`, `int`, `double`, `LocalDate`, `LocalDateTime`, `ArrayList`, `enum` (như `MembershipType`, `OrderStatus`) đã Serializable sẵn, không cần làm gì.
- Nếu **quên** thì không lưu được. `FileHelper.save` sẽ in `Cannot save data/products.dat: model.FoodProduct` (tên lớp bị thiếu) và dữ liệu không được ghi. Thấy dòng này thì kiểm tra lại các lớp trong danh sách.
- Khi sau này **đổi cấu trúc lớp** (thêm hoặc bớt trường), file `.dat` cũ có thể không đọc được. Chương trình sẽ in thông báo và chạy tiếp với dữ liệu rỗng. Lúc đó xóa file `.dat` cũ trong thư mục `data/` là xong.

## 3. Công cụ có sẵn: `helper/FileHelper`

Chỉ có 2 hàm:

```java
FileHelper.save(String fileName, Object data);          // ghi ra file
FileHelper.load(String fileName, T emptyData);          // đọc từ file
```

- `load` trả về `emptyData` nếu **chưa có file** (lần chạy đầu) hoặc **file bị hỏng**, nên chương trình không bao giờ dừng vì file.
- Tên file có sẵn dạng hằng số: `FileHelper.PRODUCTS`, `CUSTOMERS`, `ORDERS`, `RETURNS`, `STOCK_MOVEMENTS`. Các file nằm trong thư mục `data/` ở thư mục gốc dự án và được tạo tự động khi ghi lần đầu:

| File | Nội dung |
|---|---|
| `data/products.dat` | Danh sách sản phẩm |
| `data/customers.dat` | Danh sách khách hàng |
| `data/orders.dat` | Danh sách đơn hàng (kèm các dòng hàng) |
| `data/returns.dat` | Danh sách phiếu trả hàng |
| `data/stock_movements.dat` | Lịch sử thay đổi tồn kho |

Ví dụ dùng trực tiếp:

```java
List<String> names = new ArrayList<>(Arrays.asList("Noodle", "Milk"));
FileHelper.save("data/demo.dat", names);

List<String> back = FileHelper.load("data/demo.dat", new ArrayList<String>());
// back chứa "Noodle", "Milk"
```

## 4. Các bước làm cho một Repository

Làm lần lượt 3 bước. Ví dụ dưới đây là **sản phẩm** (TASK-20); các loại khác làm y hệt, chỉ đổi tên lớp và tên file.

### Bước 1: cho model implements Serializable

Thêm `implements Serializable` cho lớp được lưu (và các lớp nó giữ làm trường, nếu chưa có):

```java
public class FoodProduct implements Serializable {
```

### Bước 2: đọc file khi tạo repository

Trong constructor, thay vì tạo list rỗng thì đọc từ file:

```java
// Trước
public FoodProductRepository() {
    this.products = new ArrayList<>();
}

// Sau
public FoodProductRepository() {
    this.products = FileHelper.load(FileHelper.PRODUCTS, new ArrayList<FoodProduct>());
}
```

Lần chạy đầu chưa có file thì danh sách rỗng, đúng như cũ.

### Bước 3: ghi file sau mỗi thay đổi

Viết một hàm `save()` riêng, rồi gọi ở **mọi hàm làm thay đổi danh sách**: `add`, `update`, `deleteById`:

```java
private void save() {
    FileHelper.save(FileHelper.PRODUCTS, products);
}

@Override
public void add(FoodProduct item) {
    products.add(item);
    save();
}

@Override
public void update(FoodProduct item) {
    int index = indexOf(item.getProductId());
    if (index >= 0) {
        products.set(index, item);
    } else {
        products.add(item);
    }
    save();
}

@Override
public boolean deleteById(String id) {
    int index = indexOf(id);
    if (index < 0) {
        return false;
    }
    products.remove(index);
    save();
    return true;
}
```

Không cần sửa `Main`, service hay controller: repository tự đọc khi tạo và tự ghi khi thay đổi.

**Lưu ý quan trọng:** dữ liệu chỉ được ghi khi có gọi `add`, `update` hoặc `deleteById`. Nếu code lấy đối tượng ra rồi sửa trực tiếp (ví dụ `product.setQuantity(...)`) mà **không gọi `repository.update(...)`** thì thay đổi đó chỉ nằm trong bộ nhớ và sẽ mất khi tắt chương trình. Các service hiện tại đã gọi `update` sau khi sửa; làm tính năng mới thì nhớ giữ thói quen này.

## 5. Demo: chạy thử để thấy dữ liệu còn sau khi tắt

Sau khi xong 3 bước ở trên cho sản phẩm:

1. Chạy chương trình, vào **1. Manage Food Products** rồi **1. Add Food Product**, thêm sản phẩm `P01`. Thoát chương trình (`0`).
2. Thư mục `data/` giờ có file `products.dat`.
3. Chạy lại chương trình, vào **Manage Food Products** rồi **4. View All Food Products**: sản phẩm `P01` vẫn còn.

Chạy thử không qua menu, bằng một đoạn code ngắn:

```java
public class Demo {
    public static void main(String[] args) {
        FoodProductRepository repo = new FoodProductRepository();
        System.out.println("Products loaded: " + repo.findAll().size());
        if (repo.findAll().isEmpty()) {
            repo.add(new FoodProduct("P01", "Noodle", "Food", "Pack", 8000, 100,
                    LocalDate.now().minusDays(1), LocalDate.now().plusDays(300)));
            System.out.println("Added P01");
        } else {
            System.out.println("Found: " + repo.findAll().get(0).getName());
        }
    }
}
```

Chạy lần 1 in `Products loaded: 0` rồi `Added P01`. Chạy lần 2 in `Products loaded: 1` rồi `Found: Noodle`.

Muốn bắt đầu lại từ đầu thì xóa các file `.dat` trong thư mục `data/`. Các file `.dat` không được đưa lên Git (đã có trong `.gitignore`).

## 6. Việc cần làm theo từng thẻ

| Thẻ | Repository | Lớp phải Serializable | File |
|---|---|---|---|
| TASK-20 Save and load products | `FoodProductRepository` | `FoodProduct` | `PRODUCTS` |
| TASK-21 Save and load customers | `CustomerRepository` | `Customer` | `CUSTOMERS` |
| TASK-22 Save and load orders | `OrderRepository`, `ReturnRepository` | `Order`, `OrderDetail`, `ReturnOrder`, `ReturnDetail`, `Customer` | `ORDERS`, `RETURNS` |
| TASK-23 Save and load stock history | `StockMovementRepository` | `StockMovement` | `STOCK_MOVEMENTS` |

Khi làm xong thì xóa file `.txt` cũ cùng tên trong `data/` (`products.txt`, `customers.txt`, `orders.txt`), vì không còn dùng.

Riêng **đơn hàng** có một điểm khác: `Order` giữ tham chiếu tới `Customer`. Sau khi đọc file, `Customer` trong đơn là bản sao đã lưu, không phải đối tượng trong `CustomerRepository`. Vì vậy `OrderRepository` có thêm hàm `linkCustomers(customerRepository)` để nối lại, và `Main` gọi hàm này một lần sau khi tạo các repository. Đối tượng nào khác giữ tham chiếu tới đối tượng của repository khác thì cũng cần làm tương tự.
